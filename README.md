# neftekod: мультиагентная система поддержки решений оператора

Цепочка **АВТ → гидроочистка дизельного топлива (24-2000) → блендинг**. Система оценивает
текущее и прогнозное качество продукта, тяжесть режима и риск для оборудования, формирует и
проверяет варианты управляющих воздействий и объясняет выбор оператору — либо сообщает, что
надёжной рекомендации нет.

## Быстрый старт

```bash
pip install -r requirements.txt
python run.py all --data <папка с исходными файлами>
```

Полный прогон (`prepare → calibrate → state → validate → vak → demo → backtest → docs →
dashboard`) занимает около 30–40 минут (калибровка фильтра серы и бэктест на 2 300+ циклах). Папку с данными
можно также задать переменной окружения `NEFTEKOD_DATA`.

Отдельные шаги:

```bash
python run.py prepare --data <папка>     # разбор источников, флаги, аудит справочника
python run.py calibrate                  # config/calibrated.json (только обучающий период)
python run.py calibrate --global-search  # заново найти стартовую точку фильтра серы (десятки минут)
python run.py state                      # причинные ряды состояния в cache/
python run.py validate                   # метрики на отложенном периоде + регламент ВАК
python run.py holdout                    # внутренняя проверка фильтра серы: подбор по 2023, оценка по 2024 (десятки минут)
python run.py cycle --time "2025-10-17 20:00"   # одна карточка оператора
python run.py demo                       # 10 демонстрационных сценариев -> outputs/demo/
python run.py backtest --step 6          # весь отложенный период, частями, с продолжением
python run.py docs                       # docs/03_РЕЗУЛЬТАТЫ.md и docs/05_ИСТОЧНИКИ_ДОПУЩЕНИЙ.md
python run.py dashboard                  # outputs/dashboard.html
```

Тесты: `pytest tests/` (pytest нужен только для запуска тестов, в коде `mas/` не используется).

## Интерактивный просмотр

```bash
python tools/live_viewer/server.py 8899
```

Откройте `http://localhost:8899`. Возможности:

* воспроизведение времени с шагом 6 ч и карточка оператора на каждый момент;
* ручное задание сценарных отклонений ΔT5, ΔF9, ΔF32 с повторным расчётом;
* панель **«Допущения модели и приборов»** — редактирование в режиме реального времени (в панели только параметры,
  которые влияют на результат; их около тридцати):
  * приборы и данные: диапазоны отказа и насыщения анализаторов ПАК и Q21, шум и запаздывание
    показаний, погрешность и дрейф фильтра серы, области применения методов ЛИМС;
  * качество и риск: допустимая вероятность превышения, фоновая вероятность (порог запуска действия), сорт
    товарного ДТ для проверки смеси, горизонт прогноза;
  * надёжность: температуры начала и конца цикла катализатора (шкала фактора «катализатор близок к концу цикла»);
  * выпуск: выход гидроочищенного ДТ от сырья;
  * блендинг: режим (`product_only`, `scenario`, `manual`); данных компонентов и присадок в материалах проекта нет, поэтому
    по умолчанию товарное ДТ равно ГО ДТ, а строки рецептуры, запасов, свойств компонентов и присадок появляются, когда
    такие данные внесены в `config/settings.yaml` (раздел `blending`, формат — `tests/blending_data.py`);
  * у каждого параметра указаны тип значения (`src`), ссылка на источник (нормативный документ, литература, данные проекта
    или требование задания), описание, единицы, допустимые границы и значение по умолчанию;
    нормативные значения показаны, но не редактируются;
  * изменения приборов и ЛИМС пересчитывают фильтр серы и ряды состояния по всему периоду
    (около 10–30 с), остальные действуют сразу;
  * значения существуют только в памяти сервера: файлы конфигурации и кэш не изменяются;
    сброс возвращает значения по умолчанию, набор изменений можно выгрузить в JSON и загрузить обратно.

Параметры калибровки, не вошедшие в панель (коэффициенты кинетики, коридоры, границы факторов), в этом режиме
не пересчитываются: для них используется `python run.py calibrate`.

## Структура

```
mas/
  common.py, contracts.py, bus.py   каркас: конфигурация, датаклассы сообщений, шина
  io/          чтение источников (телеметрия, ЛИМС, ПАК, справочник тегов, формулы ВАК)
  prepare/     флаги качества, очистка ЛИМС, аудит справочника, сборка кэша
  models/      фильтр Калмана, кинетика, катализатор, T95, регламент ВАК
  calibrate/   калибровка на обучающем периоде -> config/calibrated.json
  state/       причинные ряды состояния в cache/ (считаются один раз)
  agents/      DataAgent, QualityAgent, ReliabilityAgent, OptimizationAgent,
               BlendingAgent, Orchestrator
  evaluate/    validation.json, backtest, 10 демонстрационных сценариев
  report/      карточка оператора (Markdown), docs/03_РЕЗУЛЬТАТЫ.md, дашборд
tests/         pytest, включая проверку причинности (test_causality.py)
tools/         интерактивный просмотр (live_viewer)
docs/          состав системы, данные, обоснование, результаты, дальнейшие шаги, источники допущений
config/        settings.yaml (все допущения с полем src), scheme_map.yaml, calibrated.json
```

## Принципы

1. **Нет утечки из будущего.** Калибровка — только `index < 2025-01-01`; все признаки в `cache/`
   причинны (`tests/test_causality.py`).
2. **Качество и надёжность выше ранжирования.** Недопустимый вариант отсекается до расчёта рейтинга;
   порядок в `Orchestrator.cycle`: данные → область модели → допустимость → рейтинг
   (`tests/test_orchestrator.py::test_high_rating_cannot_beat_quality_gate`). Стоимостные показатели
   не рассчитываются.
3. **Отказ — штатный ответ.** `НАДЁЖНОЙ РЕКОМЕНДАЦИИ НЕТ` / `НАБЛЮДЕНИЕ` с указанием причины.
4. **Значений без источника нет.** Каждое значение в `config/settings.yaml` имеет поля `src` (тип) и `ref` (ссылка на
   стандарт, справочный документ, данные проекта или задание; реестр — `config/references.yaml`, сводка —
   `docs/05_ИСТОЧНИКИ_ДОПУЩЕНИЙ.md`). Поле `src` принимает значения `REQUIREMENT` / `GOST` / `TASK` / `DATA` / `LIT`.
   Параметр, для которого источника нет, из системы удалён; пороги, которые можно вычислить по данным, вычисляются
   (`cache/thresholds.json`, `config/calibrated.json`). Перечень удалённых и выведенных значений — в
   `docs/02_ОБОСНОВАНИЕ.md`, раздел 16. Таблица значений с источниками входит в `outputs/dashboard.html`, ссылки показаны у
   каждого параметра в панели.
5. **Агенты общаются только через шину.** Прямых вызовов между агентами нет; журнал шины входит
   в каждую карточку (`outputs/cycles/*.json`, `outputs/demo/*.json`).

## Результаты на данных

Числа — в `docs/03_РЕЗУЛЬТАТЫ.md`. Кратко:

* аудит справочника выявляет 4 противоречия по 24-2000 и 5 по АВТ;
* фильтр серы на отложенном периоде: MAE 1.22 мг/кг (среднее двух приборов — 1.38, градиентный бустинг — 1.73), покрытие
  90 %-го интервала 0.94, медиана NIS на обучении 0.38; во внутренней проверке (подбор по 2023, оценка по 2024) фильтр и
  среднее двух приборов равны (1.41 и 1.39), преимущество фильтра вне выборки не подтверждено; прогноз серы на 4 ч уточняет уровень (MAE 1.39 против 1.68 у
  «без изменений»), но превышение нормы через 4 ч не отличает от фона (AUC 0.52);
* интервал T95 откалиброван по данным (σ = 4.04 °C), покрытие 0.91; вероятности превышения 360 °C завышены в верхней
  области (консервативно);
* порог запуска действия отсчитывается от фоновой вероятности превышения (сера 14.8 %, T95 1.1 %): бэктест —
  52 % циклов без изменений, 33 % с корректирующим действием, 10 % отказов;
* регламент ВАК (уточнённые формулы): 0 из 25 сверок пригодны — контрольной величиной остаётся ЛИМС;
* все 10 демонстрационных сценариев дают ожидаемый статус.

## Ограничения

Формулы ВАК и справочник тегов — уточнённые (`формулы_ВАК.xlsx`, `теги АВТ_24-2000.xlsx`, версии указаны в
`cache/data_summary.json`); расхождения справочника с данными перечислены в `docs/01_ДАННЫЕ.md`. Блендинг рассчитывается
сценарно: лабораторных данных по компонентам 2–3 и присадкам нет, их свойства — допущения,
изменяемые в интерактивном просмотре. Подробности — в
`docs/00_СОСТАВ_СИСТЕМЫ.md` (раздел «Ограничения») и `docs/02_ОБОСНОВАНИЕ.md`.

## Воспроизводимость

Повторный `python run.py calibrate` даёт побайтово идентичный `config/calibrated.json` (сортировка
ключей, фиксированный seed бутстрепа). Бэктест продолжаемый: результаты по частям (4 месяца)
сохраняются в `outputs/backtest_parts/` и при повторном запуске не пересчитываются.
