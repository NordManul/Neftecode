# Инструкция запуска и демонстрации

## 1. Подготовка в PyCharm

1. Откройте корень репозитория (`Neftecode`) как проект.
2. В `File → Settings → Project → Python Interpreter` создайте новый локальный
   интерпретатор `.venv` на Python 3.11–3.13.
3. В терминале PyCharm выполните:

   ```powershell
   python -m pip install --upgrade pip
   python -m pip install -r requirements-lock.txt
   ```

4. Проверьте поставку без производственных данных:

   ```powershell
   python run.py smoke
   ```

   Ожидаемый результат: `smoke: PASS`, файл
   `outputs/smoke/smoke_report.json`.

## 2. Подключение данных

Положите выданные CSV/XLSX-файлы в отдельную папку, например
`C:\NeftecodeData`. В папке должны находиться телеметрия АВТ и 24-2000, ЛИМС,
ПАК, справочник тегов и уточнённые материалы ВАК, перечисленные в
`docs/01_ДАННЫЕ.md`.

В терминале PyCharm выполните:

```powershell
python run.py prepare --data C:\NeftecodeData
python run.py calibrate
python run.py state
python run.py validate
python run.py vak
```

Для полного воспроизводимого прогона используется:

```powershell
python run.py all --data C:\NeftecodeData
```

`all` выполняет подготовку, калибровку, построение причинного состояния,
валидацию, проверку ВАК, демонстрацию, бэктест, отчёты и дашборд.

После полного прогона проверьте комплект сдачи:

```powershell
python run.py submission-check
```

Ожидаемый статус — `PASS`. При `INCOMPLETE` команда перечисляет недостающие
артефакты и подсказывает повторить полный прогон.

## 3. Обязательный показ комиссии

Запустите:

```powershell
python run.py demo
python run.py docs
python run.py dashboard
```

Покажите `outputs/demo/` и следующие сценарии:

| Файл | Что подтверждает |
|---|---|
| `01_устойчивый_режим` | нормальный режим не вызывает лишних действий |
| `02_риск_по_сере` | корректирующее управляющее воздействие |
| `03_риск_по_t95` | ограничение качества и эскалация технологу |
| `04_пак_застыл` | обнаружение аномалии анализатора |
| `05_после_пуска_нет_данных` | отказ при недостатке данных |
| `08_простой` | корректное состояние «установка не в работе» |
| `10_блендинг_сценарий` | проверка рецептуры и суммы долей |

В каждом JSON-файле есть `trace.bus_log`: полный цикл
DataAgent → QualityAgent → ReliabilityAgent → OptimizationAgent →
BlendingAgent → Orchestrator.

## 4. Интерактивный просмотр

После выполнения `state` запустите:

```powershell
python tools/live_viewer/server.py 8899
```

Откройте `http://localhost:8899`. Изменения в просмотрщике живут только в
памяти и не изменяют конфигурацию проекта.

## 5. Артефакты сдачи

* `docs/03_РЕЗУЛЬТАТЫ.md` — численные результаты;
* `outputs/dashboard.html` — единый интерактивный отчёт;
* `outputs/demo/*.md` — операторские карточки;
* `outputs/demo/*.json` — входы, оценки, ограничения и журнал обмена;
* `outputs/validation.json` и `outputs/backtest_summary.json` — проверка качества;
* `docs/07_МАТРИЦА_СООТВЕТСТВИЯ_ТЗ.md` — карта требований к реализации.

Папки `data/`, `cache/` и `outputs/` исключены из Git намеренно: входные
производственные данные и большие вычисленные результаты передаются отдельно.
